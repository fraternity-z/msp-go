# P0-P3 测试环境验收

## 评测前冻结

2026-09-06，项目负责人已授权完成 P2-B、真实质量和容量评测，并明确在测试环境执行。采用独立 PostgreSQL 数据库、独立 Qdrant 进程、测试账户和原创数学文档；模型使用管理员已激活的不可变版本。本记录中的门槛在查询评测结果产生前冻结。

- 正例语料：60 篇原创数学讲义，微积分、线性代数、概率各 20 篇；100 条预先标注的中文、英文、公式及概念辨析查询。标注由独立实现任务在检索前冻结，属于工程基准，不等同真实师生教学效果研究。
- 质量门槛：文档级 Recall@5 >= 0.90、MRR@5 >= 0.85、nDCG@5 >= 0.85；引用原文摘要和权限校验正确率 100%。去重文档后计分，同一文档多个 chunk 不重复计相关命中。
- 负例：无答案与显式拒绝权限分开记录。权限负例零泄露；无答案样本检查检索证据与 Session 引用行为，不能将最近邻结果直接视为有答案。
- 容量档：原始语料、10 万与 100 万向量。扩容使用真实文档 embedding 的显式副本；分别报告独立文本数量、向量数量和副本数量，容量结果不冒充百万独立文档质量结果。
- 延迟门槛：10 万向量、5 并发下，本地 PostgreSQL + Qdrant 检索 P95 <= 1 秒；含真实 query embedding 的完整检索 P95 <= 3 秒。100 万档与更高并发用于记录扩展趋势，不设生产 SLO。
- 成本限制：仅发送原创语料；累计文档输入最多 200 万 UTF-8 字节，查询不超过 1000 次。容量副本复用真实计算所得向量，无需重复购买相同文档 embedding。
- 一致性门槛：未完成索引不得发布；幂等重放无重复；失效租约不能提交；下线立即阻断读取；异步清理和对账恢复后差异为零；重建完成前旧代仍可用。
- 功能门槛：PDF、DOCX、TXT、MD 均通过上传、解析、分块、embedding、向量写入、PG 发布、检索和引用读取；错误码、重试、状态界面和 worker 健康指标可验证。

## 实测结果

真实质量、入库、恢复与固定容量门槛已通过，百万档扩展趋势已完成；真实无答案问答仍待调用授权，当前尚不表示 M3 已验收。

### 环境与语料

- 隔离 PostgreSQL 18.1，顺序应用 `0001` 至 `0021`；合成教师与学生账户，不对原业务数据库执行写入。配置在进程内读取既有管理员加密记录，不导出密钥。
- 管理员 active 模型 `voyage-4-large`，revision `auto-v2-e5ec9a9f2abaa010`，1024 维，Cosine，批量 32，使用供应商实际 document/query input type。
- 冻结语料 SHA-256：`2e39bd5c08561963bffa2bbb27d5380238d2ba2f937393233eb99aafbea80136`。正文合计 20,248 UTF-8 字节，60 文档各形成一个主 chunk；100 正例包括跨语言 40、公式 24、概念辨析 23、改写 13。
- 宿主机约 32 GiB RAM、32 个逻辑 CPU；Qdrant 所在 WSL 实例固定为 4 GiB RAM、2 CPU、2 GiB swap，PostgreSQL 在宿主机运行。测试库使用 `C` 字符分类，汉字的 `show_trgm` 为空；中文子串仍正确，但其索引选择性不能代表已配置 Unicode 字符分类的部署。
- Qdrant 固定 1.14.1。Windows 原生实例在大集合优化时返回路径错误，`optimizer_status` 异常且 HNSW 尚未建立；容量验收迁到既有 Ubuntu 26.04 WSL、独立 ext4 目录的同版本 Linux 实例。只绑定回环地址，未修改宿主系统配置或业务数据。

### 无答案问答门禁

5 条无答案问题涉及黎曼勒贝格引理、柯西积分公式、带位移 QR 迭代、Kolmogorov 扩张定理和马尔可夫链细致平衡，均不在这 60 篇讲义的覆盖范围。真实检索仍返回最近邻候选，这本身不代表资料能回答问题。Session 的预算、授权、历史隔离与引用传递已通过临时 Mock/真实 PG 验证，但尚无真实 Tutor 回答可供核对。

自动审批拒绝了发往管理员所配置 Tutor 服务的 5 次真实问答调用，原因是该外部目的地的调用授权尚未明确。待授权后逐条检查回答是否明确资料不足、是否将无关候选作为论据、引用是否与答案内容相符；全部通过后才能将 M3 标记为 DONE。测试限定合成账户、5 条原创问题和每条最多 8 KiB 原创检索材料，可能产生 5 次模型调用费用。

### 容量诊断与复测

首轮 10 万副本暴露资源范围查询扫描所有 chunk/manifest、词法拼接谓词无法利用正文 GIN 的问题。修复将范围查询限制为每个资源一个有效 chunk，并先通过正文 GIN/标题召回词法候选，再核对完整跨字段谓词。Linux 复测进一步发现查询规划器提前计算拼接全文谓词、整表加载候选正文；通过物化候选和逐主键加载约束执行路径，保留完整跨标题/正文匹配、原排序和 ACL。26 项等价性/权限场景通过；20 条冻结查询在 auto/custom/generic 计划下共 120 次对照均成功，Q001 从约 `3839 -> 130 ms`，最慢样本约 404 ms。

异常 Windows 实例的 10 万/5 并发原始 P95 为 4382.57 ms，SQL 修复后仍有索引优化异常。该实例 `status=red`、`indexed_vectors_count=0`，不作为容量通过证据。Linux 复测要求 optimizer 正常、HNSW 已建立、集合稳定后再采样，并记录实际已索引点数及原始配置。

10 万/百万档的 PostgreSQL 实际库大小分别为 301618879/1824569023 字节，包含本轮装载、删除和重试产生的物理空间。百万档采样后 Qdrant storage 分配空间 5184638976 字节，进程 RSS 瞬时值 637808 KiB。两档保持 1024 维 Cosine、HNSW m=16/ef_construct=100、indexing_threshold=20000 KiB、单 shard/replica、on_disk_payload=true，未启用量化或另设 mmap 参数。10 万点全部 HNSW；百万点有 995004 个 HNSW 点、12 个 segment，集合 green/optimizer ok，小尾段按默认阈值保留。

百万档首次并发装载在 438816 点发生传输失败；随后状态 green、optimizer ok，不能据此断言内存不足。确定性 ID 全量重放采用单 writer、128 点/批及有限重试，999940 个副本重放约 552.7 秒，1 次传输失败后重试成功，未改变集合参数；百万点及 PG 副本身份校验通过。运行环境切换后重新打开原数据目录，百万点仍完整，995004 点具有 HNSW，小尾段按默认阈值保留，优化器正常。装载重试与检索请求错误分别计数。

装载诊断还发现成功写操作未读取响应体，导致 HTTP 连接无法复用。修复采用有界 drain，6 类操作连续 6 次请求由 6 条连接降为 1 条；空响应、读取错误、1 MiB 边界及超限响应均通过临时 Mock/race 验证。该问题已修复，但没有将其作为前述传输失败的已证实原因。
